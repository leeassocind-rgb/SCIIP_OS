# SCIIP_OS v9 Sprint 27B — Real-Data Replay and Reconciliation

Sprint 27B executes the read-only production proof:

1. Load the immutable 2026-06-04 AIR baseline generated by Sprint 27.
2. Require the first normalized SuperSheet observation to be 2026-06-05.
3. Replay all observation JSON files in strict chronological order.
4. Generate governed candidate events through the Sprint 26 delta engine.
5. Reconstruct the final observed market state.
6. Reconcile the reconstructed state against a current AIR observation package.
7. Optionally corroborate lease and sale candidates against LeePro XLSX evidence.

No canonical writes are possible. Missing listings remain removal candidates until the configured confirmation threshold is met. LeePro matches increase evidence confidence but never force an event classification.

## Inputs

Sprint 27B intentionally consumes normalized JSON observation packages, not raw PDF text. Use the existing SuperSheet ingestion/adaptation pipeline to create one JSON package per report date. File names may contain dates, but each package should also include `snapshotDate`.

## Run

```bash
npm run run:v9:sprint27b:real-replay -- --config /absolute/path/config.json --output /absolute/path/review-package.json
```

## Certification

```bash
npm run certify:v9:sprint27b:real-replay
```
